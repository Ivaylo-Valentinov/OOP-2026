## Единично наследяване
### Наследяване

**Наследяващият (производен) клас** получава всички полета и методи от **наследения (базов) клас**, като излючение са тези, дефинирани в private секцията - до тях липсва пряк достъп от производния клас. Тук е и основната разлика между спецификаторите за достъп **private** и **protected**.

| Спецификатор | Видимост в класа | Видимост от външния свят | Видимост в производен клас |
| ------------ | ---------------- | ------------------------ | -------------------------- |
| private      | да               | не                       | не                         |
| protected    | да               | не                       | да                         | 
| public       | да               | да                       | да                         |


Наследяващият клас от своя страна също може да скрива дадени полета от наследения клас, правейки ги недостъпни за останалия свят. Това се случва чрез **спецификатор за достъп** при самото наследяване. Ако такъв не е посочен, то по подразбиране се смята за **private**. Правилото е, че член-данните от всяка секция от базовия клас попадат или в същата секция в производния, или в такава с по-строг достъп, в зависимост от спецификатора при наследяването.

| Спецификатор при наследяване | Секция от базовия клас | Секция от производния клас |
| ---------------------------- | ---------------------- | -------------------------- |
| private                      | private                | private (без пряк достъп)  |
| private                      | protected              | private                    |
| private                      | public                 | private                    |
| protected                    | private                | private (без пряк достъп)  |
| protected                    | protected              | protected                  |
| protected                    | public                 | protected                  |
| public                       | private                | private (без пряк достъп)  |
| public                       | protected              | protected                  |
| public                       | public                 | public                     |

### Конструктори
- Когато базовият клас има конструктор по подразбиране
```c++
class A {
public:
  A() { cout << "A()\n"; }
  //....
};

class B : public A {
public:
  B() { cout << "B()\n"; } //Тук ще се извика констуктора по подразбиране на A
  //Еквивалентно е на: B(): А() { cout << "B()\n"; }
  //....
};
```
- Когато базовият клас няма конструктор по подразбиране
```c++
class A {
public:
  A(char a) { cout << "A()\n"; }
  //....
};

class B : public A {
public:
  B() { cout << "B()\n"; } //Тук ще се хвърли грешка, защото А няма констуктора по подразбиране

  B(): А('a') { cout << "B()\n"; } //Използвайки инициализиращия списък можем да избегнем грешката
  //....
};
```
### Оператор за присвояване
- По подразбиране компилаторът ще създаде оператор за присвояване, който ще извика и базовият оператор за присвояване, но ако се наложи да предефинираме оператор за присвояване в класа наследник, ние управляваме дали ще се извика оператора за присвояване от базовия клас.
```c++
class A {
public:
  A& operator=(A&) {
    cout << "op=(A&)\n";
    return *this;
  }
};

class B : public A {
public:
  B& operator=(B& rhs) {
    A::operator=(rhs); //Тук се извиква базовият оператор за присвояване
    cout << "op=(B&)\n";
    return *this;
  }
};
```

### Композиция VS Наследяване
- наследяване – разпознава се чрез връзка между двата класа (“E”) 
  Студентът Е човек (наследяване между Student && Person)     
  Point3D Е Point2D с допълнителна координата (наследяване между Point3D && Point2D)
- композиция - разпознава се чрез връзка между двата класа (“ИМА”)     
  Студентът ИМА студентска книжка (в Student има поле от тип StudentCard)    
  Правоъгълникът ИМА горен ляв ъгъл (в Rect има поле от тип Point2D)

##  Шаблонни функции и класове

### Функции
- **Дефиниране на шаблонна функция**     
Чрез употребата на шаблони можем да съставим "обобщени" функции, които да се използват върху различни типове данни.   
В примера реализираме функцията swap, която можем да приложим върху два обекта, от какъвто и да е тип `Т`, стига операциите в тялото на функцията да могат да се дефинирани за него.
```c++
template <typename T>
void swap(T first, T second) {
    T temp = first;
    first = second;
    second = temp;
}
```

- Функцията може да се извика по следния начин
```c++
class User {
    //...
public:
    User& operator= (const User& other) {...}
};

int main () {
    User gosho;
    User pesho;

    swap(gosho, pesho);

    return 0;
}
```

### Класове

Примери от лекциите:
```c++
template <typename T>
class TemplateClassName {
  // … 
};


//Подразбиращи се параметри:
template <typename T = int> 
class TemplateClassName {
  //… 
};

//Всички параметри трябва да са подразбиращи се след първия такъв!
template <typename T = int, typename S = int>
class TemplateClassName {
  //… 
};

//Член-функции
template <typename T1, typename T2>
class TemplateClassName {
public: 
  T1 inlineFunc(T1 x, T2 y) { 
  // Вградена член-функция //… 
  }
  T2 testFunction(T1 x, T2 y);  // Член-функцията не е вградена private: T1 firstField; T2 secondField; };
};

template <typename T1, typename T2>
T2 TemplateClassName<T1, T2>::testFunction(T1 x, T2 y) {
  //… 
}
```

### Специалиализация:

Понякога, често с оптимизационна цел, искаме да имаме специализирана имплементация на даден шаблон за определен тип/клас. Например, бихме могли да имплементираме `Vector<bool>` като масив от _битове_, вместо от булеви стойности (които заемат по един **байт** всяка) и по този начин да намалим значително необходимата памет.

```c++
template <>
class Vector<bool> {
private:
	size_t used;
	size_t capacity;
	unsigned *bitset;

	// ...
};
```

Задаване на ново име на специализация на клас:
```c++
typedef TemplateClassName<int, double> NewNameClass;
```
